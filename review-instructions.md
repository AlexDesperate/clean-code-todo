# Инструкция для AI-ревьюера по модулю Clean Code

## 1. Цель задачи
Провести детальный анализ предоставленного JavaScript/HTML/CSS кода TODO-приложения, выявить архитектурные проблемы и запахи кода (code smells), описанные в модуле Clean Code, и сформировать подробный отчёт.

## 2. Границы проверки
* **Что проверять:** Логику работы с DOM, именование переменных и функций, дублирование кода (DRY), наличие мёртвого кода (Dead Code), избыточные комментарии.
* **Чего НЕ трогать:** Не предлагать переписывать приложение на фреймворки (React/Vue/Angular) или добавлять сборщики (Vite/Webpack). Функциональность должна оставаться прежней.

## 3. Критерий готовности
Ревью считается завершённым, когда проверены все функции приложения и составлен финальный структурированный отчёт.

## 4. Формат вывода результатов
Результат должен быть предоставлен на русском языке и сохранён в файл `review-report.md`. Каждое замечание должно строго состоять из четырёх компонентов:
1. **Место в коде:** Указание файла и строки (или названия функции).
2. **Проблема:** Суть нарушения правил чистого кода.
3. **Условие:** При каком условии проявляется проблема.
4. **Способ проверки:** Как разработчик может убедиться, что исправление работает и ничего не сломало.
